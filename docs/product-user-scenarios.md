# Product User Scenarios

## Why This Document Exists

게임 시나리오와 별개로, `사용자가 이 제품을 어떻게 쓰는가`도 정의해야 화면 플로우와 턴 길이가 흔들리지 않는다.

## Primary User Scenario

### `면접 직전 연습 사용자`

- 사용자는 특정 회사 면접을 앞두고 있다.
- 짧은 시간 안에 시나리오 질문 감각을 끌어올리고 싶다.
- 너무 긴 서술보다 `답변 순서`를 반복 훈련하고 싶다.

### Success Condition

- 한 판이 4~6분 안에 끝난다.
- 턴마다 무엇이 부족했는지 바로 알 수 있다.
- 한 판 후 다시 도전하고 싶은 느낌이 든다.

## Core Session Flow

1. 회사 이름이나 분위기를 입력한다.
2. 시나리오를 고른다.
3. 3턴 배틀을 진행한다.
4. 최종 코칭을 본다.
5. 같은 시나리오를 다시 하거나 다른 시나리오로 넘어간다.

## MVP Interaction Rule

- 한 판은 `3턴 고정`
- 한 턴당 행동 선택 `1회`
- 짧은 주관식 입력 `1회`
- 꼬리질문은 턴당 최대 `1개`

## Follow-up Design Rule

꼬리질문은 많을수록 좋은 게 아니다.

MVP 추천:

- 튜토리얼: `1개`
- 일반 시나리오: `총 2개`
- 대표 시나리오: `총 3개`

이유:

- 면접다운 압박은 유지된다
- 그러나 사용자 피로가 과도하게 쌓이지 않는다
- 포켓몬식 턴 템포가 유지된다

## Turn Time Budget

- 상태 읽기: 3~5초
- 행동 선택: 5~10초
- 짧은 답변 입력: 15~30초
- 판정과 꼬리질문 읽기: 5~10초

권장 총합:

- 한 턴 30~50초
- 한 판 4~6분

## Tailoring Rule

회사 이름 입력은 `세계관 몰입`에 쓰고, MVP에서는 시나리오 로직을 완전히 갈라놓지 않는다.

바뀌는 요소:

- 면접관 이름
- 인트로 대사
- 시각 테마
- 일부 용어

초기에는 바뀌지 않는 요소:

- 상태 시스템
- 턴 구조
- 채점 기준

## Role Split Review

이번 설계에 맞는 서브 에이전트 역할은 아래처럼 나누는 게 적절하다.

- `시나리오 수집가`: 공개 기술 글에서 incident archetype 추출
- `시니어 면접관`: 답변 구조와 꼬리질문 spine 설계
- `포켓몬 배틀 시스템 디자이너`: 상태/기술/전장 연출 설계
- `플래그십 시나리오 작가`: 실제 3턴 스크립트 작성
- `UX 라이터`: 텍스트 박스 문장과 코칭 문구 다듬기
- `디자이너`: 스프라이트, HUD, 전투 화면 스타일 정의
- `시니어 개발자`: 데이터 구조와 구현 경계 고정
