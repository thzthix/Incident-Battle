# 대표 시나리오 3

## 제목

`결제 또는 외부 API 장애`

## 시나리오 목적

- 외부 의존성과 내부 병목을 분리해서 사고하는지 본다.
- 복구 속도와 데이터 정합성을 함께 챙기는지 본다.
- 잘못된 재시도나 성급한 조치가 더 큰 피해를 만들 수 있음을 인지하는지 본다.
- 고객 영향과 커뮤니케이션을 답변에 포함하는지 본다.

## 사건 브리프

`금요일 저녁 8시 12분, 프로모션 시작 7분 후 결제 성공률이 97.8%에서 71.4%까지 떨어졌습니다. 카드 결제 승인 단계의 timeout 비율은 2%에서 28%로 치솟았고, 간편결제는 성공률이 조금 낮아졌지만 완전히 무너지진 않았습니다. 앱 서버 CPU는 40% 수준으로 안정적인데, 외부 PG 응답 p95는 480ms에서 4.2s로 상승했고 내부 주문 저장 write latency도 35ms에서 620ms까지 같이 올라왔습니다. 지금은 하루 매출이 가장 큰 저녁 피크 시간대라 전체 결제를 오래 막을 수 없고, 성급한 재시도나 수동 재처리는 중복 결제 위험을 키울 수 있습니다. 이 상황에서 무엇을 먼저 확인하시겠습니까?`

## 현실감 앵커

- `시간 맥락`
  금요일 저녁 8시 12분, 프로모션 시작 7분 후
- `영향 사용자`
  모바일 앱 카드 결제 사용자가 가장 크게 영향받고, 간편결제는 일부 지연
- `측정 신호`
  결제 성공률 97.8% -> 71.4%, 외부 PG p95 480ms -> 4.2s, 내부 write latency 35ms -> 620ms
- `상충 단서`
  앱 서버 CPU는 높지 않지만 외부 PG와 내부 저장 쓰기 모두 느려짐
- `제약`
  피크 시간대라 전체 결제 차단이 어렵고, 일부 스키마 후처리는 이미 비동기로 진행 중
- `잘못된 대응 리스크`
  무분별한 재시도는 부하를 증폭시키고, 성급한 수동 재처리는 중복 결제나 주문 누락을 만들 수 있음

## 시작 전장 상태

- `묶인 회선`
  외부 의존성 때문에 대응 선택지가 제한된다.
- `급한 불`
  결제 흐름 장애라 사용자 피해와 매출 손실이 크다.
- `핵심 시간대`
  지금 판단이 몇 분만 늦어져도 영향이 빠르게 커진다.

## 좋은 답변의 뼈대

이 시나리오에서 플레이어가 반복적으로 익혀야 할 구조는 아래다.

1. `결제 성공률과 영향 범위부터 본다.`
2. `외부 PG 지연과 우리 내부 병목을 분리한다.`
3. `피크 시간대 제약 안에서 우회나 제한으로 피해를 먼저 줄인다.`
4. `재시도 폭증과 중복 결제 같은 정합성 리스크를 관리한다.`
5. `복구 후에는 reconciliation, 고객 안내, 재발 방지까지 말한다.`

## 최종 코칭 포인트

- 결제 장애에서는 `복구 속도`와 `정확성`을 같이 봐야 한다.
- 외부 API 문제여도 `우리 쪽 완화 수단`을 먼저 설명해야 면접답변이 강해진다.
- `사용자 영향 -> 외부/내부 분리 -> 완화 -> 정합성 검증 -> 공지/예방` 순서를 지키면 높은 점수를 받을 가능성이 크다.
- 좋은 답변은 똑똑한 원인 추정보다 `안전한 대응 순서`를 먼저 보여준다.
