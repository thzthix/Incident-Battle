# 역할 분장

## 결론

대체로 맞는 방향이었는데, 지금 단계에서는 역할을 조금 더 실무적으로 자르는 편이 좋다.

너무 캐릭터성만 강한 역할보다 `산출물 기준`으로 나누는 게 더 효율적이다.

## 추천 역할 세트

### 1. 시나리오 수집가

목표:

- 기술블로그와 공개 장애 사례에서 인터뷰형 원석을 뽑는다.

산출물:

- 사건 브리프
- 핵심 사용자 영향
- 진단 난점
- 긴급성 포인트

### 2. 면접 코치

목표:

- 좋은 답변의 뼈대와 자주 틀리는 답변 패턴을 정리한다.

산출물:

- 강한 답변 예시
- 흔한 실수
- 최종 코칭 포인트

### 3. 배틀 시스템 디자이너

목표:

- 현실 사건을 전장 상태와 행동 기술로 번역한다.

산출물:

- 상태 12개
- 행동 10개
- 상성 규칙

### 4. UX 라이터

목표:

- 텍스트박스, 면접관 대사, 결과 문장을 전투 톤에 맞게 쓴다.

산출물:

- 턴별 전투 대사
- 꼬리질문
- 결과 코치 문장

### 5. 시니어 개발자

목표:

- 기획을 바로 구현할 수 있는 데이터 구조와 화면 흐름으로 바꾼다.

산출물:

- 시나리오 JSON 포맷
- 상태머신
- API 스펙

### 6. 아트 디렉터

목표:

- Sinnoh풍 감성을 오리지널 자산으로 번역한다.

산출물:

- 화면 레이아웃 방향
- 도트 캐릭터 방향
- 배경/텍스트박스/HUD 규칙

## 캐릭터성 역할을 붙이고 싶다면

이렇게 덧씌우면 된다.

- `토스 10년차 주니어`: 빠른 우선순위와 핀테크 압박감 검토
- `당근 20년차 시니어`: 실서비스 장애 대응과 사용자 영향 검토
- `포켓몬 오타쿠`: 전투 문법과 상태 연출 검토
- `포켓몬 디자이너`: 스프라이트와 HUD 감성 검토

하지만 이 역할들은 `본업 역할` 위에 입히는 flavor로 쓰는 게 좋다.
