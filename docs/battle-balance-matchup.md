# Battle Balance Matchup

## 목적

이 문서는 면접 배틀 MVP에서 사용하는 `전장 상태 12개`와 `플레이어 기술 10개`의 상성 규칙을 고정한다.
목표는 다음과 같다.

- 유저가 `상태를 읽고 행동을 고르는 재미`를 느낀다.
- 백엔드가 `일관된 점수`를 계산할 수 있다.
- 같은 기술도 `상태에 따라 가치가 달라지는 배틀성`을 만든다.

1. `압박감`
2. `변경 흔적`
3. `흐린 로그`
4. `묶인 회선`
5. `급한 불`

11. `복구 창`
12. `불만 누적`

1. `범위 파악`
2. `변경 추적`
3. `관측 세우기`
4. `의존성 점검`
5. `우선순위 선언`

10. `상황 공유`

## 1. 상태 x 행동 효과 체계

MVP에서는 포켓몬식 타입 상성을 단순화해서 아래 3단계만 쓴다.

- `강함`
  설명: 현재 상태에 직접 맞는 대응이다.
  효과: 높은 기본 점수와 긍정 피드백을 준다.
- `보통`
  설명: 완전히 틀리진 않지만 핵심을 직접 찌르진 못한다.
  효과: 평균 점수와 중립 피드백을 준다.
- `약함`
  설명: 지금 턴의 핵심 상태를 제대로 다루지 못하거나, 순서가 어긋난다.
  효과: 낮은 점수와 보완 피드백을 준다.

상성 판단 원칙은 아래 네 가지다.

1. 상태는 `지금 가장 어려운 문제`를 뜻한다.
2. 기술은 `플레이어가 먼저 꺼내는 대응`을 뜻한다.
3. 좋은 기술은 상태의 리스크를 줄이거나, 판단에 필요한 근거를 만든다.
4. 약한 기술은 맞는 말이어도 `지금 먼저 하기엔 순서가 어긋난다`.

## 2. 상태별 강함/보통/약함

### `압박감`

- 강함: `우선순위 선언`, `범위 파악`, `상황 공유`
- 보통: `변경 추적`, `관측 세우기`, `원인 분리`
- 약함: `즉시 우회`, `되돌리기`, `의존성 점검`, `우선 차단`

이유: 압박감은 장황한 분석보다 `무엇부터 할지`가 중요하다.

### `변경 흔적`

- 강함: `변경 추적`, `되돌리기`, `원인 분리`
- 보통: `관측 세우기`, `범위 파악`, `우선순위 선언`
- 약함: `즉시 우회`, `의존성 점검`, `우선 차단`, `상황 공유`

이유: 최근 배포나 설정 변경이 의심되면 먼저 변경 이력과 롤백 가능성을 봐야 한다.

### `흐린 로그`

- 강함: `관측 세우기`, `범위 파악`, `가정 명시` 대신 현재 행동 풀에선 `원인 분리`
- 보통: `우선순위 선언`, `의존성 점검`, `변경 추적`
- 약함: `되돌리기`, `즉시 우회`, `우선 차단`, `상황 공유`

이유: 근거가 부족할 때는 추측보다 관측 보강과 범위 파악이 우선이다.

### `묶인 회선`

- 강함: `의존성 점검`, `즉시 우회`, `상황 공유`
- 보통: `원인 분리`, `범위 파악`, `우선 차단`
- 약함: `되돌리기`, `변경 추적`, `우선순위 선언`, `관측 세우기`

이유: 외부 API나 파트너 의존성이면 우리 시스템만 보지 말고 우회와 격리를 같이 봐야 한다.

### `급한 불`

- 강함: `범위 파악`, `즉시 우회`, `우선 차단`
- 보통: `우선순위 선언`, `상황 공유`, `관측 세우기`
- 약함: `변경 추적`, `의존성 점검`, `원인 분리`, `되돌리기`

이유: 핵심 사용자 흐름 장애는 복구와 완화가 먼저다.

### `확산 조짐`

- 강함: `우선 차단`, `범위 파악`, `즉시 우회`
- 보통: `상황 공유`, `원인 분리`, `의존성 점검`
- 약함: `변경 추적`, `되돌리기`, `관측 세우기`, `우선순위 선언`

이유: 장애가 퍼질 조짐이면 먼저 blast radius를 줄여야 한다.

### `핵심 시간대`

- 강함: `우선순위 선언`, `범위 파악`, `즉시 우회`
- 보통: `상황 공유`, `우선 차단`, `관측 세우기`
- 약함: `변경 추적`, `원인 분리`, `의존성 점검`, `되돌리기`

이유: 피크 타임에는 깊은 분석보다 사용자 영향과 빠른 완화가 중요하다.

### `과부하`

- 강함: `범위 파악`, `우선 차단`, `즉시 우회`
- 보통: `관측 세우기`, `원인 분리`, `상황 공유`
- 약함: `되돌리기`, `변경 추적`, `의존성 점검`, `우선순위 선언`

이유: 요청량 폭증은 부하 완화와 확산 억제가 먼저다.

### `느린 저장소`

- 강함: `의존성 점검`, `원인 분리`, `관측 세우기`
- 보통: `범위 파악`, `우선 차단`, `즉시 우회`
- 약함: `되돌리기`, `변경 추적`, `상황 공유`, `우선순위 선언`

이유: DB나 큐 병목은 저장소 병목인지 앱 병목인지 분리해야 한다.

### `가설 붕괴`

- 강함: `원인 분리`, `관측 세우기`, `범위 파악`
- 보통: `의존성 점검`, `상황 공유`, `우선순위 선언`
- 약함: `되돌리기`, `변경 추적`, `즉시 우회`, `우선 차단`

이유: 기존 추정이 틀렸다면 판단을 리셋하고 새 근거를 세워야 한다.

### `복구 창`

- 강함: `되돌리기`, `즉시 우회`, `우선 차단`
- 보통: `우선순위 선언`, `상황 공유`, `범위 파악`
- 약함: `관측 세우기`, `변경 추적`, `의존성 점검`, `원인 분리`

이유: 안전한 완화 수단이 열려 있다면 너무 오래 분석만 하면 손해다.

### `불만 누적`

- 강함: `상황 공유`, `범위 파악`, `즉시 우회`
- 보통: `우선순위 선언`, `우선 차단`, `의존성 점검`
- 약함: `변경 추적`, `원인 분리`, `관측 세우기`, `되돌리기`

이유: 실패가 쌓일수록 사용자 체감과 소통이 중요해진다.

## 3. 백엔드 구현용 단순 점수 규칙

MVP에서는 `상태별 상성 점수 + 턴 보정 + 짧은 답변 보정`으로 계산한다.

### 3-1. 기본 점수

현재 활성 상태 2~4개 중 `중심 상태 1개`와 `보조 상태 1개`를 정한다.

- 중심 상태: 이번 턴 질문의 핵심
- 보조 상태: 상황을 더 어렵게 만드는 보조 조건

선택한 기술이 각 상태에 대해 받는 점수:

- 강함: `+20`
- 보통: `+10`
- 약함: `0`

턴 기본 점수 계산식:

`base_score = 중심 상태 점수 + 보조 상태 점수`

예:
- 중심 상태에 강함 `20`
- 보조 상태에 보통 `10`
- 기본 점수 `30`

### 3-2. 턴 목표 보정

턴마다 기대하는 사고 단계가 다르므로 보정치를 둔다.

- 1턴 목표: 상황 파악, 우선순위
  가산 행동: `범위 파악`, `우선순위 선언`, `변경 추적`, `관측 세우기`
- 2턴 목표: 즉시 대응, 원인 분리
  가산 행동: `즉시 우회`, `우선 차단`, `의존성 점검`, `원인 분리`, `되돌리기`
- 3턴 목표: 마무리, 공유, 재발 방지
  가산 행동: `상황 공유`, `원인 분리`, `범위 파악`

보정:

- 턴 목표에 잘 맞음: `+10`
- 턴 목표와 어긋남: `0`

### 3-3. 짧은 답변 보정

자유 입력은 1~2문장만 받으며, 아래 신호를 본다.

- 사용자 영향 언급
- 우선순위 언급
- 최근 변경 언급
- 로그/메트릭 언급
- 외부 의존성 언급
- 복구/완화 언급
- 조건부 분기 언급
- 소통/공유 언급

보정:

- 핵심 신호 2개 이상 포함: `+10`
- 핵심 신호 1개 포함: `+5`
- 핵심 신호 없음: `0`

### 3-4. 감점 규칙

- 증거 없이 과한 조치 제안: `-10`
- 사용자 영향/우선순위 전혀 없음: `-5`
- 새 정보가 나왔는데 기존 가설만 반복: `-10`

### 3-5. 턴 총점

`turn_score = base_score + turn_bonus + text_bonus - penalties`

권장 턴별 상한:

- 1턴: `35`
- 2턴: `35`
- 3턴: `30`

최종 총점:

`final_score = turn1 + turn2 + turn3`

## 4. 구현용 데이터 구조 제안

상성표는 아래처럼 저장하면 구현이 쉽다.

```json
{
  "변경 흔적": {
    "strong": ["변경 추적", "되돌리기", "원인 분리"],
    "neutral": ["관측 세우기", "범위 파악", "우선순위 선언"],
    "weak": ["즉시 우회", "의존성 점검", "우선 차단", "상황 공유"]
  }
}
```

또는 기술 기준으로 역인덱스를 둬도 된다.

```json
{
  "되돌리기": {
    "strongAgainst": ["변경 흔적", "복구 창"],
    "neutralAgainst": ["압박감", "범위 파악 없음 상태"],
    "weakAgainst": ["묶인 회선", "가설 붕괴", "과부하"]
  }
}
```

MVP에서는 `상태 기준 맵`이 더 단순하다.

## 5. 같은 기술이 상태 따라 달라지는 예시 3개

### 예시 1. `되돌리기`

- 좋음: `변경 흔적`
  이유: 최근 배포가 의심되고 복구 창이 있으면 매우 합리적이다.
- 약함: `묶인 회선`
  이유: 외부 API 장애가 핵심이면 우리 배포를 롤백해도 문제를 못 건드릴 수 있다.

### 예시 2. `관측 세우기`

- 좋음: `흐린 로그`
  이유: 근거가 부족한 상태라 로그, 메트릭, 알람 확보가 핵심이다.
- 약함: `복구 창`
  이유: 안전한 우회나 롤백 창이 열려 있을 때 관측만 오래 하면 복구 타이밍을 놓친다.

### 예시 3. `즉시 우회`

- 좋음: `급한 불`
  이유: 핵심 사용자 흐름이 깨졌다면 degraded mode나 fallback이 큰 도움이 된다.
- 약함: `가설 붕괴`
  이유: 기존 가설이 틀린 상황에서 무작정 우회만 반복하면 문제를 더 흐리게 만들 수 있다.

## 6. MVP 밸런스 운영 규칙

- 한 턴에는 기술 4개만 보여준다.
- 보여주는 4개 중:
  - 강함 1~2개
  - 보통 1개
  - 약함 1개
- 모든 턴에 항상 같은 정답 기술이 뜨지 않게 한다.
- `범위 파악`과 `우선순위 선언`은 1턴에서 자주 보이되, 항상 최강 기술로 만들진 않는다.
- `상황 공유`는 3턴에서 빛나게 하고, 1턴에서는 보통 이하로 자주 둔다.
